## Resolution

Both failed runs already had a valid cached headset size (2112x2304 per eye)
and logged that the user engine INI already contained 4224x2376. The following
successful runs found the INI back at 1600x1200 and rewrote it. This is not
failed DLL injection, missing OpenXR, or merely learning the first headset size.
Configuration regeneration when switching installations is a plausible cause,
but these logs do not identify the writer or prove why it happened.

The old mode hooks appended the desired size, allowing engine validation to
select another mode. The candidate offers only the cached mode when Auto is
active, using the engine's own mode validation so its scene targets and
backbuffer agree. It does not independently resize the backbuffer. Custom/Off
and uncached first launches retain their previous behavior. Formats with no
native modes remain empty. The first headset discovery still needs a relaunch.

The old `this run is sized` diagnostic compared only cached headset dimensions,
not actual output. It now describes that comparison accurately, and device
creation explicitly reports a mismatch. Real startup recovery still requires
a headset run; synthetic enumeration tests cannot prove engine behavior.

## Combat and arm swing

Run 2's missing `GetSocketWorldLocationAndRotation` function caused permanent
failure of all combat initialization, including motion melee. The setting was
On; runtime readiness was false. This is not explained by diagnostic settings.
Run 1 found the function in the same Steam installation, so it is not simply
absent from that game version. A background scan during loading can miss
objects; the exact reason this lookup failed was not recorded.

The candidate retries incomplete discovery up to three total attempts, separated
by two seconds, preserving background scanning and all parameter/ABI checks.
Failed thread creation and incompatible ABI still fail closed. Initialization
also waits for the supplied pawn to equal the published player pawn: the live
probe's hook filters on that identity. That guards a possible explanation for
run 3's zero-entry probe; the log alone does not establish it as the cause.

Arm swing was enabled in run 2. Its sampler and forward-input calculation do
not depend on ArmSwingDebug. Historical `metrics only` log text was misleading
and has been corrected. A separate defect did exist: turning both arm swing and
its logging off stopped the shared samples used by melee. Motion punching now
keeps sampling active independently. Neither log nor simulation verifies what
an unperformed arm-swing test would have felt like in the headset.

## Smoke remains open

Both successful runs show thousands of world UP draws duplicated per 600-frame
window, plus the per-eye haze and shadow paths. The relevant rendering modules
have no changes between the pre-release source commit a9442b4 and v0.2.1-alpha.
These counters do not identify the particular smoke material reported by the
user. No speculative shader change was made.

The installed executable hashes differ. The installation defaults inspected
match, while one local generated engine INI differs from the shared user INI
(including PhysXEnhanced); that is not proof which settings each run consumed.
Do not change graphics settings based on these files alone.

Next evidence: on the same scene/checkpoint and viewing direction in each
installation, enable VR settings > Troubleshooting > Debug Overlay, close the
menu, and press Backspace while looking at the smoke. Backspace is gated by
Debug, so an unmodified release with Debug off will not capture. It records
paired effect images and ordered draw traces; a brief capture stall is expected.
Turn Debug Overlay off afterward. Preserve both run logs/capture directories.

## Validation and deployment status

- x86 build and static analysis completed; existing advisory warnings remain.
- Production mode-hook tests cover Auto-only selection, invalid indices/null
  outputs, unsupported formats, custom appended modes, Off, and no-cache startup.
- Production combat initialization tests cover late metadata recovery, bounded
  permanent failure, cooldown, player identity, no overlapping workers, and
  game-thread-only hook installation/calls.
- Production arm-swing calculation produces full forward input with debugging
  off, stops on stick-back and held grip; shared punch sampling survives arm
  swing off. Existing menu and combat gesture regressions pass.

These fixes are a local candidate, not a published release or headset-verified
result. The installed Steam and working development builds are left available
for the smoke comparison. The three-file candidate ZIP is staged locally under
`.analysis/four-runs-20260919/` without replacing the published release ZIP.
