# Authored pipe-top exits

The reported run shows a false negative on roof pipe `5145EE00`:

- The old handover started at Z 5670, descended 151 UU, then pushed upward.
- The move-property trace reported `ClimbState=1` during the roof animation.
- The 300-frame timeout nevertheless marked the pipe permanently refused.
- The game finished successfully at frame 23762. After death, the same volume
  pointer remained in the refused list, so the next climb never attempted an exit.

The state reader missed the successful transition because its runtime offset was
published before the cooked-owner fallback resolved `ClimbState`. The diagnostic
probe used the fallback successfully; the handover continued with offset -1.

The old top was collision-bounds maximum Z minus a headset-tuned 90 UU margin.
That physical stop was above the step from which the game starts its root-motion
exit. The descent worked around that mismatch, but capability was being inferred
from a timed attempt rather than the authored data.

## Replacement

`TdLadderVolume` exposes `bCanExitAtTop`, `GetLastStep`, `GetLadderLocation`, and
`GetClosestStep`. `TdMove_Climb.HandleClimbAction` checks the closest/last step
and the exit flag, then calls `ExitAtTop` with animation 4 or 5 according to the
current climbing hand. Those declarations and scripts were verified in the
local shipped TdGame package.

The mod now resolves the exact property owners/types and function parameter
layouts on the existing discovery thread. On the game thread it reads the
active move's `Ladder`, queries the authored final step, and publishes a snapshot
tagged with pawn, move, volume and timestamp. Geometry queries are cached only
for that live climb; the capability and state are refreshed.

An upward hand pull is clamped to that authored step on a roof-capable pipe.
The game thread calls the normal `ExitAtTop` only after checking the native
closest-step result, position, current pawn/move/volume, idle animation and
precise-location state. It chooses the game's left/right-hand variant. There is
no synthetic down/up sequence, forced state byte, collision override, or roof
teleport. The game's own function starts and completes root motion.

Once state 1 is observed, the mod leaves the body and hands to the game until
climbing ends. An unaccepted request times out after three seconds and restores
hand control; it does not label the pipe roofless. Releasing that attempt by
moving back below the step, or leaving/re-entering the pipe, allows another try.
Pawn changes invalidate the cached source and request. An absent active Ladder
cannot fall back to a stale volume still referenced by the pawn.

Pipes with `bCanExitAtTop=false` keep the measured physical top stop. Missing or
invalid exit metadata disables automatic exits without inventing capability or
running a descent probe. Hand reach continues to use the existing tuned bounds.

## Validation

`tools/test-pipe-exit.ps1` compiles the production mod into a standalone fixture.
It exercises cooked owner lookup, parameter validation, actual game-call
dispatch, both hand variants, authored-height clamping, committed animation past
the former timeout, death/new pawn on the same volume, failed-request recovery,
roofless pipes, stale identities, menu gating and cached geometry queries.

The build and existing VR-menu, combat, and arm-restore regressions are also run.
The native animation's visual alignment and completion need an in-headset pass
on the roof pipe, followed by death and a second climb.
